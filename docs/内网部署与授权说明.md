# 内网部署与授权说明

> 本文为兼容保留的简版说明。完整的构建、离线交付、续期、备份、回滚和验收流程请以[《内网离线交付与续期部署手册》](内网离线交付与续期部署手册.md)为准。

本说明面向**内网(无外网)交付场景**:免费版 PyArmor 混淆 + 授权到期日烧录 + 全自包含 Docker 部署。

## 1. 交付物清单(build/dist/)

| 文件 | 说明 |
|---|---|
| `complaint-dedup-validator-intranet-<到期日>.tar.gz` | 应用镜像(代码已混淆,授权日期烧录) |
| `postgres-16-alpine.tar.gz` | 数据库镜像 |
| `compose.intranet.yaml` | 编排文件(内置 PostgreSQL，自动初始化表) |
| `env.intranet.example` | 模型连接配置模板 → 复制为 `config/.env` |
| `SHA256SUMS.txt` | 交付包校验清单 |

> 免费版 PyArmor 对单文件大小存在限制，超过限制的模块可能保留明文，构建日志会输出 `PLAINTEXT` 警告。交付前必须核对构建日志并确认保护边界。

## 2. 构建流程(在有外网的构建机上执行)

```powershell
# 构建(源码测试 → 免费版 PyArmor 混淆 → 镜像内测试 → 导出)
.\scripts\build_intranet.ps1 -ExpireDate 2027-09-01
```

构建流水线:

```
源码 pytest 全绿
  → Docker builder 阶段(Linux):
      生成 licensing_conf.py(EXPIRE_DATE 烧录)
      使用免费版 pyarmor gen 混淆(运行时文件与 Linux 目标平台匹配)
  → Docker tester 阶段:对混淆产物跑全量 pytest(失败即构建失败)
  → runtime 阶段:仅复制混淆产物 + templates/static/alembic,不含明文源码
  → docker save 导出 tar.gz
```

**续期**:换一个 `EXPIRE_DATE` 重新执行构建脚本、交付新镜像即可,客户侧 `docker load` + 重启。

## 3. 客户内网部署步骤

```bash
# 1. 加载镜像
docker load -i complaint-dedup-validator-intranet-2027-09-01.tar.gz
docker load -i postgres-16-alpine.tar.gz

# 2. 准备目录并配置模型
mkdir -p config
cp env.intranet.example config/.env
vi config/.env        # 只修改 LLM_BASE_URL/LLM_API_KEY/LLM_MODEL 等模型配置

# 3. 启动；API 自动检查连接、建表和校验结构，worker 等待 API 健康后启动
docker compose -f compose.intranet.yaml up -d

# 4. 验收
curl http://127.0.0.1:28765/                 # 200
docker compose -f compose.intranet.yaml ps   # postgres healthy / api healthy
```

数据库账号、密码、数据库名和内部连接地址已由 Compose 固定管理，实施人员不需要填写。PostgreSQL 不映射宿主机端口，只允许应用容器通过内部网络访问。上传文件和导出结果保存在 Docker 命名卷中，由 Compose 自动创建，不需要手工创建目录或调整权限。如果启动日志提示发现旧版表或当前表字段缺失，系统会拒绝启动并明确列出问题，应由项目维护人员处理。

浏览器打开 `http://<服务器IP>:28765`,上传一份全量工单 Excel,再按时间窗口创建比对任务。

### 可选外部模型配置

当前确定性判重主流程不调用大模型；以下配置仅为后续候选归一化扩展保留，不影响本期全量同步和时间窗口比对:

```ini
LLM_BASE_URL=http://<内网推理机>:<端口>/v1
LLM_API_KEY=EMPTY              # vLLM 通常不校验,占位即可
LLM_MODEL=<vLLM 服务的模型名>
LLM_SEND_ENABLE_THINKING=false # 默认关闭;确认推理端支持 enable_thinking 字段后才开启
```

## 4. 授权机制说明

- **到期日期**:构建时通过 `--build-arg EXPIRE_DATE=YYYY-MM-DD` 烧录进混淆代码,常量存于
  `licensing_conf.py`,以 **Asia/Shanghai 日历日**判断,过期即停止服务。
- **三类强制检查**:
  1. API 启动时(lifespan)→ 到期则容器启动失败,反复重启,`docker ps` 一眼可见;
  2. 全局 HTTP 中间件 → 运行中跨过到期日,所有页面请求返回 403 中文提示页;
  3. worker 启动、领取任务和执行任务前 → 到期后不再处理新任务。
- **时钟回拨守卫**:首次启动时间写入数据库 `license_state` 表;系统时间早于该值超过 1 天
  将拒绝启动,防止"改时钟续命"。
- 新基线迁移为 `20260908_0001_full_corpus_baseline`，包含 `license_state` 和全量工单/时间窗口比对所需表。

## 5. 常见问题

| 现象 | 处置 |
|---|---|
| API 容器反复重启,日志含"服务授权已于 … 到期" | 授权已到期,联系供应商续期换取新镜像 |
| 日志含"疑似时钟回拨" | 校准服务器系统时间(NTP)后 `docker compose -f compose.intranet.yaml up -d` 重启 |
| 构建日志出现 `PLAINTEXT (trial limit)` | 免费版单文件限制提示；核对日志并确认交付保护边界 |
| 数据库连接失败 | 检查 PostgreSQL 容器状态和 `docker compose logs postgres`，无需修改数据库密码 |

## 6. 与互联网部署(compose.yaml)的差异

| 项 | 互联网版 | 内网版 |
|---|---|---|
| 代码来源 | `./app:/app:ro` 挂载明文源码 | 混淆代码烧入镜像,无源码挂载 |
| 数据库 | 外部 PostgreSQL | compose 内置 postgres:16-alpine |
| LLM | 兼容配置保留,当前主流程不调用 | 兼容配置保留,当前主流程不调用 |
| 授权 | 无 | EXPIRE_DATE 烧录 + 时钟回拨守卫 |
| 镜像构建 | 客户侧可构建 | 构建机统一构建,`docker load` 交付 |
