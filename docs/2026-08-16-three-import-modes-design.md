# 三入口历史库与每日增量设计

## 目标

将导入界面从四个模式精简为三个真实业务入口，隐藏后端词典细节，并使用现有历史表和当天表完成一次可追溯的硅基流动真实任务。

## 入口与职责

系统只允许创建以下三类新批次：

1. `bootstrap_history`：只上传历史表，重新构建历史语料库、事件和标准化数据。批次成功后切换为当前活动历史库；旧活动库保留数据库快照用于回滚。
2. `bootstrap_compare`：首次同时上传历史表和当天表。历史表先在 staging 中完成建库和冻结，随后当天表只匹配该 staging 历史库；两阶段均成功后一次性提交为活动库和当天结果。
3. `daily_increment`：只上传当天新增表，要求系统存在活动历史库；当天记录匹配历史事件并写入数据库，成功后追加到活动语料库。

旧 `correction` 模式不再允许新任务选择。历史数据库中已有的 correction 批次保留为只读审计记录，不出现在新建任务入口。

## 历史库替换

冷启动采用 staging 和原子切换：

- 上传文件先写入独立批次和临时来源标识；
- 解析、标准化、事件分组和导出全部完成后，才更新活动库指针；
- 切换前的活动库标记为历史快照，不删除记录；
- 任一阶段失败时保持旧活动库可用，失败批次保留错误和原始文件；
- 新冷启动成功后，日常增量只读取最新活动库。

首次联合比对不允许当天数据反向影响历史库的标准键；历史 B 完成冻结后才处理当天 A。

## 词典边界

街道、锚点和事项词典继续保存在 PostgreSQL，并由后端归一化流程使用。普通前端不显示词典版本、词典项、审核、导出或词典链接；任务进度只显示业务阶段和结果。词典仍随批次版本化，便于回滚和审计。

## 模型与真实数据

真实任务使用配置文件中的硅基流动接口，模型请求允许发送已脱敏完整文本。历史文件为 `半年以来历史表.xlsx`，当天文件为 `2026.8.12-12时-8.13-12时（当天）.xlsx`。真实运行结果必须写入 PostgreSQL，事件成员、匹配依据、模型响应失败和导出文件均可追溯。

## 前端变化

- 首页导入模式下拉框只保留“历史库冷启动”“首次联合比对”“每日新增”；
- 冷启动只显示一个历史文件上传控件；
- 首次联合比对显示历史文件和当天文件两个控件；
- 每日新增只显示当天文件控件；
- 删除 correction 相关提示和字段；
- 删除所有词典状态、词典版本和词典审核入口；
- 历史库统计改为当前活动库统计，批次页保留业务进度、事件和工单结果。

## 验收标准

- 新建任务接口拒绝 `correction`，接受另外三种模式及对应文件组合；
- 页面不出现“词典”字样和词典链接；
- 历史冷启动成功后活动库记录数与历史文件有效行数一致；
- 当天任务只追加当天记录，不重建历史事件；
- 首次联合比对先完成 B 再处理 A；
- 使用硅基流动真实 API 完成一次当天任务，数据库存在批次、记录、事件和模型审计结果；
- 失败冷启动不会改变原活动库；
- 旧测试和新增三模式集成测试通过。
