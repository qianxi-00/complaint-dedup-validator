# 投诉判重系统修复说明

## 修复目标

针对《投诉判重系统改造计划》实现后的代码审查结果，修复历史重建不可执行、重建后数据来源丢失、条件导出与页面筛选不一致、`cannot_links` 跨代次误用，以及事项筛选接口残留问题。

## 修复内容

### 1. 历史重建 CLI

- 增加 `history_rebuild.run()`，支持生成重建审核报告。
- `scripts/rebuild_history.py --help` 可正常执行。
- 默认重建只生成 `review_required` 候选代次，不自动切换活动代次。
- 支持 `--activate-generation ID` 和 `--rollback-generation ID`，二者与重建动作互斥。

### 2. 历史数据完整性

- `InputRecord` 增加 `data_source` 字段。
- 重建读取并保留 `history`、`daily`、`correction` 来源。
- 从结构化字段补回缺失的 `处理部门`、`办结时间`、`所属部门`，同时保留原始 JSON。
- 新代次继续保留处理部门、办结时间和导出所需原始业务字段。

### 3. 条件导出

- 条件导出的事件 ID 查询固定使用完整的事件、街道和成员连接。
- 修复地区/街道与“隐藏单例”组合时重复连接导致的 SQL 错误。
- 页面列表查询同步使用 `EventFilters` 中的每日工单和隐藏单例条件。
- 导出仍按命中事件导出完整事件成员，工作表结构和公式注入防护不变。

### 4. 人工禁止关系

- 重建只映射两个端点都属于旧活动代次的 `cannot_links`。
- 未映射的其他代次记录不会参与新代次冲突拆分。
- 冲突记录继续拆为独立单例，旧事件保留归档/活动状态更新。

### 5. 事项筛选清理

- 从 `EventFilters`、事件列表统计和筛选项接口中移除事项筛选。
- 事件列表中的“事项”展示列和内部事项字典仍保留，用于事件归类和显示。

## 验收标准

- 目标回归测试全部通过。
- 全量 `uv run pytest -q` 通过。
- `uv run python scripts/rebuild_history.py --help` 返回 0。
- SQLite 数据库可执行 `uv run alembic upgrade head`。
- 未执行生产数据库迁移、历史重建或代次激活；生产操作仍需备份、迁移、dry-run、人工审核后进行。
